# 验证报告 · 秋千跳跳

这份报告只写**实际跑过、实际看过**的东西。哪些是量出来的、哪些是看截图判断的、哪些没验证，分开写。

本项目由 GLM-5.4 开发，提示词只有 README 末尾的那一句。

| 项目 | 值 |
| --- | --- |

**交互检查**（`app_check.py`）逐项是这些：场景就绪；标题上写着“本项目由 GLM-5.4 开发”；画质默认自动、从最高档起步；空格开始，开始那一下不算蓄力；一开始有操作提示；按住鼠标蓄力，画面下沿的蓄力条真的画出来了（有粗细、不透明、横着居中）；松开鼠标、空格、`↑` 键各跳一次，都落在下一个秋千上；荡过两个秋千狼开始追，左上角出现距离；`Esc` 暂停时规则停住，再按继续；点暂停按钮不顺带蓄力；暂停里进设置，选“流畅”马上换过去、选“极致”换回来；打开落点辅助后按住时画出弧线；暂停菜单上按空格是继续、不蓄力；`M` 静音；按得太轻掉进云海，卡片上写着原因和分数，最高分存进浏览器；空格和 `R` 再来一局；被狼追上、旧秋千断，各有各的提示；回到标题；“怎么玩”里有四种秋千；设置和最高分刷新以后还在；改窗口大小画布跟着变；手机横屏上说明写的是“按住屏幕”、一屏放得下，手指按住蓄力、松手落在下一个秋千上；竖屏也能开始。

**画面检查**（`pixel_check.py`）扫了 14 帧：标题、开局、蓄力、空中、第 16 个和第 34 个秋千、狼追近、被抓、结算、掉进云海，手机横屏的标题和游戏，竖屏的标题和游戏。每一帧都把 HDR 场景缓冲读回来数了一遍，不是有限数的像素是 0，最亮的值是 1.5 ～ 3.7（被抓那一帧的白闪）。纯黑的像素是 0，纯白最多 1.3%。另外量了三件事：站着不动时隔 0.5 秒的两帧平均相差 0.009（云在飘、树在晃、兔子在喘气，画面不是死的）；狼追近时四角的蓝红比从 0.97 变成 1.13（四角发紫）；被抓那一下平均亮度从 0.54 升到 0.93（白闪）。

**声音**（`audio_check.py`）量的是主输出上的电平（峰值 / 均方根）：风声的底子 0.08 / 0.023，起跳 0.38 / 0.040，落地 0.29 / 0.042，落在正中 0.41 / 0.051，滑下去 0.30 / 0.044，掉进云海 0.24 / 0.040，落进云里 0.15 / 0.029，狼嚎 0.25 / 0.046，旧秋千吱呀 0.20 / 0.032，秋千断 0.29 / 0.045，被抓 0.52 / 0.074，结束 0.17 / 0.032，破纪录 0.29 / 0.054；按住蓄力 0.12 / 0.048；狼追到 12 米以内吼声和心跳起来（0.34 / 0.060），打发远了散回去（0.06 / 0.022）；暂停 0 / 0，音量调到 0.3 是 0.02 / 0.008，静音 0 / 0，取消静音回到 0.06 / 0.021。没有削波（最高的峰值是 0.52），每个音效都压得过风声。

**场景审计**（`audit_scene.py`）：标题画面里约 270 个网格（10 来座岛的岛身和秋千、兔子 31 个、远处的岛 9 个、鸟 32 个……），外加狼的 76 个；整个场景 21 万个三角形，一个画面里画 17 ～ 19 万个、约 165 次绘制，狼在画面里时约 340 次绘制、26 万个三角形。144 份几何（19.6 MB）、41 个材质、7 张程序化贴图（1.8 MB，最大的是 512 × 256 的木板）、23 个着色器程序、一盏投影的太阳和一层半球光，阴影贴图 2048。没有“材质要顶点色而几何没有”的，没有“几何带着顶点色而材质不认”的，几何的属性、索引里没有不是数字的值。

**内存**：先把金色、宽板凳、裂缝三种秋千各传送一次（它们的贴图头一回画到才上传到显存），再一路传送 12 次（第 3 ～ 260 个秋千）并让机器人打了 16 秒——显存里的几何体稳定在 68 ～ 69 个、贴图 12 张，场景里的对象 404 ～ 416 个（岛的装扮不同，会差一些）。拆掉的岛放干净了。

**单帧渲染耗时**（含阴影和全部后期；渲染后逼着显卡同步，每个画面先连续画 40 帧预热，再取 40 帧的平均；标题、开局、中段、狼在画面里）：

| 分辨率 | 流畅 | 均衡 | 极致 |
| --- | --- | --- | --- |
| 1280 × 720 | 0.37 ～ 0.69 ms | 0.33 ～ 0.70 ms | 0.42 ～ 0.59 ms |
| 1920 × 1080 | 0.32 ～ 0.71 ms | 0.40 ～ 0.60 ms | 0.30 ～ 1.29 ms |

最吃的是狼在画面里的时候：狼是 76 个零件，每个都要再画一遍影子，绘制次数从 175 涨到 335。**这些数字有浮动**：前后三轮里“狼在画面里”的那个画面从 0.6 到 1.8 毫秒都有（最慢的一次是 1280 × 720、极致档），原因没有细查（多半是显卡的频率和别的进程）。都离 60 帧的预算很远。

**启动**：检查链里报的“场景就绪”是 7.4 秒，那是把无头浏览器冷启动也算进去的时间。

**两处会干扰测量的环境因素**，都和页面本身无关：

- **远程桌面**：这台机器经常是通过远程桌面连着用的。远程会话里的虚拟显示器是 32 Hz 的时候，浏览器里的 `requestAnimationFrame` 最高就是每秒 32 次。所以帧率说明不了本机显示器上的表现，只报单帧耗时。这件事也影响玩法：按住多久如果按帧数累加，32 赫兹下会有 ±30 毫秒的误差，所以按下和松开的事件都带着时刻、推进到那个时刻再处理——交互检查里“松手落在下一个秋千上”在这台机器上是过的。
- **能效核**：Windows 有时会把无头的浏览器排到能效核上，同一帧的耗时能慢一倍多。检查脚本把浏览器钉在性能核上。

## 3. 看过的画面

以下都是打开截图逐张看的，属于目视判断，不是数值：

- 标题（桌面 1600 × 900、1280 × 720，手机横屏和竖屏）；开局、蓄力、空中、落在正中、金色秋千、裂缝的旧秋千、秋千断、狼追近、被扑倒、结算、手机横屏——也就是 README 里那 13 张。
- 交互检查顺手截的 15 张界面：暂停、设置、怎么玩、触屏上的蓄力。
- 放大看的局部：狼的头、身子、腿和脚下的云；兔子站在金色秋千上；画面左缘的云；标题文字背后的那一块。
- 逐层隔离着看的：三层积云和前景云各自单独画出来是什么样、叠在场景上是什么样；云的贴图本身（透明度和明暗两个通道）。

看到并改掉的（大致按先后）：

- **泛光让半个画面变黑**：在半浮点的后期管线上加 `UnrealBloomPass`，读回来的像素有五到七成是黑的。去掉泛光，要发光的地方（狼的眼睛、星星）自己带一片叠加的柔光。
- **整个画面发灰**：轮廓光太强、色表太淡、卡通着色的中间一段给得太亮。轮廓光从大片面上的强光收到 0.12，色表加深，中间段 0.76 → 0.58，曝光 0.6，饱和度提一点。
- **所有的东西在左右方向上压成一片**：重写拼网格的工具时漏了把顶点的 x 写进去。
- **岛的几何里全是 NaN**：算上下文的那一步返回的字段叫 `depth`，用的时候写成了 `D`。单元测试里加了“所有数都是有限数”。
- **建一棵树的树冠要 36 毫秒**：合顶点太慢。自己写了一个接缝处共用顶点的球，拼网格改成按“不重复的顶点”算，每一步降到 3.6 毫秒以内。
- **围巾的飘带是黑的**：法线一开始是零、上传以后没有再标“改过”。一开始就填好朝镜头的法线。
- **裂缝的旧秋千用的是普通木板**：材质表里的键是 `old`，取的时候写的是 `cracked`；断的时候刷在侧面的色带和铃铛还挂在半空。
- **空翻的那一跳永远停在空中**：清理 import 时把还在用的 `launch` 删掉了，页面每帧报错。是画面检查里“松手以后一直不落地”暴露的。
- **跳到第 5 个秋千时机器人掉了**：间隔表的最后一项越界，取到了 `undefined`。现在每个间隔写在前一个秋千上，提前一步定下来。
- **自动画质一上来就降到最低档**：拿 24 毫秒当线，而远程桌面下帧间隔本来就是 31 毫秒。改成和这台机器跑出来的最快帧比。
- **在还留着焦点的按钮上按空格，会把那个按钮再点一遍**：蓄力被取消、暂停菜单又弹出来。点过的按钮把焦点放开。
- **金色秋千每次都新建两个小几何，用完不放**：换成共用的。
- **前景云把下半屏罩白**：贴着镜头飘的几朵云个头太大，飘过时用一层奶白把秋千、树干和狼都盖住了。放大看狼的特写才发现；逐层关掉对比以后确定是这一层。压到只从画面下沿探进来一点。
- **狼脚下的云像一摊墨迹**：原来是几片半透明的深色软片子叠在一起，在草地上看着像阴影。换成九团压扁的球，和岛、树同一种材质，一起被太阳照、一起投影。
- **云上有一级级的直边**：一开始以为是贴图到方块边上还没透明，把贴图的轮廓往里收了，没用。逐层隔离、把对比度拉开才看清：云海是一块不透明的平面，云片伸到它下面的部分被它切平，同一团云里各张片子远近略有不同，切口的高低差几个像素，叠起来成了台阶。让云片在自己的着色器里贴着云海面的高度淡出。顺手删掉了完全藏在云海面以下、根本看不见的那一层。
- **所有积云悄悄消失了**：上一步给云的大小加注释时，注释写在了行中间，把同一行后半截的两个属性（随机相位、压扁比例）注掉了，片子的相位成了 NaN。是场景审计里“属性里有 4 个不是数字的值”抓出来的。修回去以后顺便把远处的积云抬高了一些，不然远景太空。
- **标题文字背后的柔光太浓**：中心 90% 不透明，把身后的树洗得发白，看着像一块带直边的白板。逐像素量过（界面开、关各截一张相减），那不是合成的错误，是一团正常的椭圆柔光——地平线和两根树干把它切成了像矩形的样子。调到 72%，小字加了一圈光晕保证可读。
- **“+3 / 完美”飘在离兔子很远的地方**：飘字是按落地那一瞬的屏幕位置放的，镜头一移它留在原地。改成记世界坐标，主循环每帧重新算。
- **狼吼一直在响，别的声音全被盖住**：声音检查第一次跑，底噪的均方根是 0.19（正常该是 0.02），每个音效都只比底噪响一点点。原因是颤音的振荡器直接加在了吼声的音量参数上，闸门关着它也在 ±0.35 之间摆。改成先过闸门、再乘颤音。修掉以后才看得见每个音效真正的电平，又把太轻的四个（起跳、滑下去、落进云里、旧秋千吱呀）调响了一些。
- **蓄力条没有画出来**：样式表里一条规则的尾巴上写了 `//` 注释，CSS 不认，它把下一条规则——蓄力条——的选择器一起吞掉了。交互检查原来只断言了类名和宽度，所以一直是过的；现在断言它在屏幕上真的有粗细、不透明、居中，并且加了一条“样式表的每一条规则浏览器都认”（故意把那个注释放回去试过，报的是丢了 `#hud .charge`）。
- **“快跳！”和“完美 +3”叠在一起**：落在旧秋千正中的时候两行字飘在同一个位置。“快跳！”挪到上面一层。
- **手机上的按钮写着“空格 / 回车”**：看竖屏和横屏的截图才发现，触屏设备上标题的“开始游戏”和菜单的“返回”还带着键盘按键。触屏上不显示这两个提示，交互检查里电脑和手机两头各加了一条断言。
- **云的深度排序和名单对不上**：这个是读代码时发现的，画面上看不出——排序打乱了缓冲区的顺序，对应的那份名单没跟着换。镜头一动整份都会重写，所以没出过错，但逻辑是错的，顺手改对。

## 4. 玩法上的数字：哪些是试出来的，哪些是定的

**用机器人试出来的**（`src/core/bot.js`；每种手速 200 局，机器人每次落地以后先犹豫一段时间再起跳）：

| 每跳犹豫多久 | 中位数荡了多少个秋千 | 四分之一 ～ 四分之三 | 怎么结束的 |
| --- | --- | --- | --- |
| 不到 0.5 秒 | 400（上限） | — | 都没死 |
| 落点带 ±0.25 米的误差 | 400（上限） | — | 都没死 |
| 0.6 ～ 1.4 秒 | 166 | 137 ～ 194 | 全部被狼追上 |
| 1.0 ～ 2.0 秒 | 42 | 38 ～ 44 | 145 局被追上，55 局秋千断了 |
| 1.5 ～ 3.0 秒 | 22 | 17 ～ 25 | 109 局秋千断了，91 局被追上 |

**按观感定的常数**（没有对应的真实测量）：

- 重力 22 米/秒²、起跳角 46°、按满 1.1 秒、初速 6.5 ～ 15.6 米/秒：要的是“按一下跳一下”那种干脆的手感。秋千自己的摆动倒是按真实的重力算的。
- 路的间隔从 4.6 米长到 8 米、高度差不超过 0.55 米、从第 6 个起有的秋千会晃、三种特殊秋千各占一成：是看着机器人模拟的结果调的。目标不是“平均能活多久”，而是“手快就一路走下去、一犹豫就被追上、越往后越不能等”。
- 狼的速度 1.35 米/秒起步、每往后一个秋千加 0.045、封顶 2.9，落后 34 米以上猛追、3 米以内放慢：同上。
- 模拟的是机器人，不是人。机器人的时机是算准的，犹豫的时间是均匀随机的；真人看秋千、按下去的反应都不是这样。

## 5. 没验证的

- **只在 Edge + 这一张显卡上跑过**，而且以无头模式为主。Firefox、Safari、别的显卡（尤其是集成显卡）都没测。
- **本地显示器上的帧率没有量过**：测试时这台机器是通过远程桌面连着用的，所以拿得出手的只有单帧渲染耗时。
- **声音没有听过**：只量了电平，音色、响度是否合适、狼嚎像不像，没有经过耳朵。
- **难度的手感只能人来判断**：狼追得紧不紧、旧秋千断得快不快、完美要得多准，都是机器人模拟加估计，没有真人试过。
- **画面的好坏**：哪些地方好看、哪些地方还糙，是看截图的判断。
- **手机和平板**只在无头浏览器里用模拟的触屏事件点过（按住蓄力、松手起跳、横屏和竖屏的排版），没有在真机上跑过；真机上的帧率、发热、浏览器地址栏的遮挡都没看。
- **自动画质**降档和升回的逻辑只在代码里走过，没有在慢的机器上看它真的降档。

## 6. 做不到的

- **模型全是代码生成的**。兔子、狼、树、岛在玩法那个距离（画面宽 10 ～ 19 米）上认得出来、经得住看；再贴近就能看出是球和胶囊拼的。
- **狼、云海、浮岛是创作**，没有现实的依据；跳跃的重力是调快了的。
- **没有关卡、道具、排行**，只有一路往前跳和身后的狼。

## 7. 怎么复现

```bash
npm install                     # three + esbuild，只有重新打包时需要
npm run prod                    # 压缩版 app.js
npm test                        # 16 项，不需要浏览器
pip install playwright pillow numpy   # 浏览器检查需要
python tools/qa/run_all.py      # 9 项，约五分钟，日志写进 docs/evidence/
```

想单看一项：`python tools/qa/perf.py --sizes 1920x1080 --quality 2`、`python tools/qa/gallery.py --only wolf,caught`。想看某个画面：`window.__game.warp(20, { wolf: 6 })` 把兔子放到第 20 个秋千上、狼摆在身后 6 米，`window.__game.freeze(true)` 把规则停住再截图。

# 验证报告 · 深海王城

这份报告只写**实际跑过、实际看过**的东西。哪些是量出来的、哪些是看截图判断的、哪些没验证，分开写。

本项目由 GLM-5.4 开发，提示词只有 README 末尾的那一句。

**画面检查**（`pixel_check.py`）扫了 43 帧：标题上 5 个时刻 × 4 种水质共 20 帧，巡游的 16 个镜头，王座厅的 5 个时刻，手机上的标题和潜泳。没有非有限的像素；纯黑的像素只有巡游和厅内画面的电影黑边（26% 上下），以及夜里加上朦胧水质时暗下去的角落（2%）。顺带确认了一件事：水越浑，远处的海水并没有更亮——浑浊表现为变暗、变糊，不是发白。

**声音**（`audio_check.py`）量的是主输出上的电平（峰值 / 均方根）：水声的底子 0.25 / 0.062，鲸 0.55 / 0.15，沉船的呻吟 0.40 / 0.11，吐气泡 0.36 / 0.098，和声 0.38 / 0.11，静音 0 / 0，夜里的底子 0.25 / 0.073。没有削波，静音是真的没声。

| --- | --- | --- | --- |
| 1280 × 720 | 3.3 ～ 4.4 ms | 6.0 ～ 8.2 ms | 6.6 ～ 8.7 ms |
| 1920 × 1080 | 4.3 ～ 5.0 ms | 7.2 ～ 9.8 ms | 7.7 ～ 10.7 ms |

极致档 1920 × 1080 逐个画面：标题 10.13、南门 9.99、王座厅 9.17、珊瑚花园 10.66、巨藻林 7.74、夜里的南门 8.65 毫秒。

**这些数字有浮动。** 同一个包前后跑了三轮，极致档 1920 × 1080 的标题是 8.3 ～ 10.1 毫秒、珊瑚花园 10.7 ～ 11.1 毫秒、巨藻林 7.7 ～ 8.3 毫秒，原因没有细查（多半是显卡的频率和别的进程）。珊瑚花园最吃几何（一帧 1600 万个三角形、1150 次绘制）。前两轮里流畅档的数字是错的——量到一半档位被自动画质升了上去（见第 3 节），修掉以后才有上面的数；所以每一行现在都把实际档记进日志。

剩下的一秒半没有拆开：搭城的几何（石像的网格化在里面，单独在 Node 里量是半秒左右）、建鱼群和大动物、头几帧都不在上面的表里。检查链里报的“场景就绪”是 8.4 ～ 12.2 秒，那是把无头浏览器冷启动也算进去的时间。

**在真实窗口里另打开过一次**（`python tools/qa/real_window.py`）：系统 Edge 弹出一个 1600 × 900 的窗口，按回车开始巡游、按 `T` 下水、按住 `W` 游了两秒，控制台是干净的，自动画质停在极致档没降。4 秒里巡游 221 帧、潜泳 220 帧，帧间隔的中位数是 18.1 毫秒（一成到九成：17.7 ～ 18.8），画一帧本身 8.1 毫秒。**这不是本地显示器上的帧率**：做测试时这台机器的远程桌面会话是断开的（`query session` 里是 Disc，`EnumDisplaySettingsW` 查不到显示器），18 毫秒是断开的会话里合成器的节奏，只说明真实的窗口里跑得起来、不卡。

**两处会干扰测量的环境因素**，都和页面本身无关：

- **远程桌面**：这台机器经常是通过远程桌面连着用的。远程会话里的虚拟显示器是 32 Hz 的时候，浏览器里的 `requestAnimationFrame` 最高就是每秒 32 次；这次在断开的会话里量到的是约 55 次。两种情况下的帧率都说明不了本机显示器上的表现，所以只报单帧耗时。
- **能效核**：这台机器的 CPU 是 6 个性能核 + 4 个能效核。Windows 有时会把无头的浏览器排到能效核上，同一帧的耗时能慢一倍多。检查脚本把浏览器钉在性能核上；平时看的时候浏览器在前台，本来就跑在性能核上。

## 3. 看过的画面

以下都是打开截图逐张看的，属于目视判断，不是数值：

- 标题、巡游的 16 个镜头、潜泳时的界面（罗盘、深度、地名）、暂停菜单、设置面板、操作说明、手机上的标题和触屏控件。
- 五个时刻下王座厅的里面和外面；彩窗落在地砖上的光斑（换时刻、换窗口的角度，看光斑连不连得成片）。
- 贴着看的近景：南门守望者的脸、侧脸、后脑勺、两只手、胸口、肚子、腰带、下摆；巨像的脸和肩膀；沉船的甲板和船头；村落的圆屋；桥洞的内顶面；城墙头和檐口上的附生生物；城墙上的砌块贴图、铺地、大理石。
- 贴图的样张：石灰岩、铺地、大理石、青铜、琉璃瓦、朽木，以及焦散和水面法线的对照图。
- 城堡、沉船、村落、神庙的几张远景；断崖的崖壁；夜里加亮以后看灯笼照到的地方。

看到并改掉的（按发现的顺序）：

- **铺地的板缝乱七八糟**：抖动格子的 Voronoi 里，格心坐标带着列号和行号，算距离时又加了一遍。
- **珊瑚长在水面上、碎砖堆埋在地下 35 米**：墙上的生长点漏了台地的高度，偏殿的碎砖堆把绝对高度当成了相对高度。巨像的金肋少了同一个偏移，飘在水面上 26 米。
- **放样曲面的法线是 NaN**：在定义域的边界上求法线时越出了一步（船尾的平底、龙骨线这种宽度收到 0 的地方）。
- **礁石顶上的珊瑚埋在石头里、桥拱肩上的珊瑚浮在空中**：改成按石头自己的坐标查高度表；桥洞的内顶面单独登记朝下的生长点。
- **厚墙里透不进光、光斑发黑**：侧墙减薄、窗子开大、下午太阳的方位挪到离西墙法线 30°，光斑才成气候；光斑的三角形绕向是反的，在法线 / 深度的预通道里算出来朝下，被环境光遮蔽压黑。
- **换画质以后画面花掉**：没有监听窗口大小，像素比一变悬浮物的投影系数就成了 NaN。补上监听；画质的值统一成字符串。
- **第一次看到一样东西卡两三秒**：着色器等到物体进视野才编译。加载画面里先把所有程序编好，再一个材质一个材质各画一遍。
- **灯笼的数量一变，着色器全部重编译**：点光源按距离开关，数量在 1 到 10 之间变，每变到一个新数字卡两三秒。改成 10 盏永远在，不用的强度置 0。
- **巨藻近黑**：顶点色和实例色乘了两遍；又补了叶子背着光时的透光。
- **夜里的亮度不对**：昼夜系数的公式把范围压到了 −6 到 −2，应该是 −6 到 +2。
- **石像像关节拼起来的木偶**：长袍、手臂、头各是各的放样曲面，肩和手臂之间有裂缝，袍子是根光滑的管子。重写成一个符号距离场再网格化。中间走了三步弯路——腰带上的带子被衣褶的脊顶穿出锯齿、肚子上又窄又浅的沟贴近了是一块块黑斑、头和身子两套网格的接缝在脖子上留下一圈锯齿——改成只留宽而缓的起伏、细格子伸进粗格子、断口藏在腰带底下才干净。
- **石像上的三叉戟悬在半空**：戟的底尖停在基座上方 0.6 米。伸到基座上。
- **长在石像上的桌珊瑚浮在水里**：生长点是照着旧石像拍的坐标。改成按石像自己的坐标给，再用场把表面上的点找出来；巨像三叉戟上的脑珊瑚也挪到了肩上、头发上、小臂底下和披风背面。
- **近处影子的边缘是锯齿**：阴影盒半径 150 米，4096 的贴图一格 7 厘米。收到 100 米以后，同一机位的对照截图里，礁石和柱子落在沙上的影子、胡子落在胸口上的影子，边缘干净了；远景里看不出 100 米以外没有影子。
- **选了流畅档，几秒后被升回均衡**：“画质有没有被固定”用的是 true / false，而档位 0（流畅）也是假值，自动画质的逻辑把它当成“没固定”，帧一快就升档。是性能表里“流畅档”的绘制次数和均衡档一样多才看出来的。改成自动是 null、固定是档位数字，交互检查里加了一条断言。
- **声音的底子和混响重写了一遍**：噪声缓冲改成 4 秒无缝循环的；棕噪声和混响的冲激响应重写（7 个早期反射、随时间衰落的低通尾音）；沉船的呻吟换成三根锯齿波过低通、带通和随时间变化的增益。改前改后只有电平可量，听感没有人听过。

## 4. 水下的光学：哪些是算出来的，哪些是定的

**按物理关系算的**（都有单元测试比对 JS 和 GLSL 两套实现，或者比对闭式解和数值积分）：

- 斯涅尔定律（折射率 1.333）：太阳折射进水里最多离竖直 48.6°，方位不变；水面的透射率按未偏振的菲涅耳公式。等价的另一面是斯涅尔窗：从水下往上看，正上方约 97° 的锥角以内能看到水面上的世界，以外是全反射。
- Beer–Lambert 律：每个通道的消光系数各自乘下去；视线上的透过率、散射光的积分（闭式解）都按它来。
- 深水波的色散关系 ω² = g·k：17 列波，24 米一个周期。水面、焦散和光束用的是同一组波。
- 焦散的亮度是 1 / |雅可比行列式|：波面把光聚到哪儿、散到哪儿。
- 大气散射：瑞利和米氏、透射率的查找表、夜空的底光。

**按观感定的常数**（没有对应的真实测量）：

- 视线的消光系数（红、绿、蓝）是每米 0.094、0.036、0.020，“清澈”这一档。**比真实的外海偏清**：按真实的吸收，40 米深处红光在两三米内就没了，整座城只剩单色蓝。
- 日光在水里的逐通道吸收取得很温和，相当于把光源的颜色校正回来；蓝调交给天光。所以背光处红光掉到蓝光的三成，被太阳照到的地方亮而中性。
- 天光和水的散射光相对日光的亮度：物理上两者该一样亮，但那样远处全糊成一片亮蓝，城立不出来。水“黑”一点。
- 月光比真实亮得多；灯笼的青色光、发光的明珠是创作。
- 曝光和景深增益按画面定；镜头每下潜一米会自动提亮一点，模拟眼睛的适应。

**形态上照着真实的样子做的**（没有量过尺寸，比例是看着对的）：巨藻的一茎到底、螺旋排列的窄叶和叶根的气囊，脑珊瑚一道道的脊，砗磲的外套膜，两心拱、玫瑰窗、扶壁和哥特式侧堂。**数量和尺寸是估的**：城的半径、桥的长短、每片海床上礁石和珊瑚的多少，都是按画面排的。

## 5. 没验证的

- **只在 Edge + 这一张显卡上跑过**，而且以无头模式为主。Firefox、Safari、别的显卡（尤其是集成显卡）都没测。
- **本地显示器上的帧率没有量过**：测试时这台机器是通过远程桌面连着用的（最后量真实窗口的那次，会话还是断开的），所以拿得出手的只有单帧渲染耗时。真实窗口里那 18 毫秒的帧间隔是断开的会话里的数字，不代表本机显示器上的表现。
- **声音没有听过**：只量了电平，音色、响度是否合适、鲸和呻吟像不像，没有经过耳朵。
- **巡游的节奏、潜泳的手感**（灵敏度、速度、转身快慢）只能人来判断；设置里的灵敏度滑块有没有一个合适的默认值，没人试过。
- **画面的好坏**：哪些地方好看、哪些地方还糙，是看截图的判断。写实到什么程度、和真实的海底像不像，没有对照过照片或视频，只能靠观感。
- **手机和平板**只在无头浏览器里用模拟的触屏事件点过（摇杆、升降、疾游、拖着看），没有在真机上跑过；真机上的帧率、发热、浏览器地址栏的遮挡都没看。
- **自动画质**降档和升回的逻辑只在代码里走过，没有在慢的机器上看它真的降档。

## 6. 做不到的

- **模型全是代码生成的**。主角们（王座厅、石像、沉船、彩窗）近看是认得出、经得住两三米的；再贴近就能看出面数和格子——石像的脸和手是 1.5 厘米的格子，袍子是 3 厘米的，礁石和巨藻是低面的多边形。没有扫描、没有雕刻、没有法线贴图级别的皮肤细节。
- **水里的能见度、月光的亮度是按好看调的**，不是按真实的洋流、浮游生物和水质。
- **没有任务、收集、战斗**，只有看和游。碰撞体是简化的几何（圆、墙段、方盒），披风的下摆、细的枝条、鱼的身子挡不住人。
- **城是虚构的**：没有一座真实的沉城做依据，建筑的比例是哥特式的，但布局和细节是创作的。
- **彩窗的花样、灯笼、明珠的光是创作**，沉船和村落也是。

## 7. 怎么复现

```bash
npm install                     # three + esbuild，只有重新打包时需要
npm run prod                    # 压缩版 app.js
npm test                        # 54 项，不需要浏览器
pip install playwright pillow   # 浏览器检查需要
python tools/qa/run_all.py      # 9 项，约十一分钟，日志写进 docs/evidence/
```

想单看一项：`python tools/qa/perf.py --sizes 1920x1080 --quality 2`、`python tools/qa/gallery.py --only gate,guardian`；想在弹出来的真实窗口里看一眼：`python tools/qa/real_window.py`（会开一个 Edge 窗口，按回车巡游、下水游两秒，截图后自己关掉）。想看某个机位：写一个 JSON（每个机位一段摆镜头的 JS），`python tools/qa/views.py x.json --out shots/x`，会顺手拼成一张总图。

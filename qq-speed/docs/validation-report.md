这份报告只写**实际跑过、实际看过**的东西。哪些是量出来的、哪些是看截图判断的、哪些没验证，分开写。

本项目由 GLM-5.4 开发，提示词只有 README 末尾的那一句。

## 2. 跑了什么，结果如何

下表是 2026-11-26 夜里到 27 日凌晨在最终发布包上跑的一轮（`python tools/qa/run_all.py`），11 项全部通过。每项的完整输出在 `docs/evidence/`。

| 命令 | 查的是什么 | 结果 |
| --- | --- | --- |
| `npm test` | 不开浏览器：赛道中心线（闭环、曲率、路宽、区段净距）、车辆物理与漂移喷射、比赛规则与道具逻辑、大气模型 JS / GLSL 两套实现是否一致、时刻配色 | 40 项全部通过；赛道自检 TRACK OK |
| `game_check.py drive` | 用真实的键盘事件开一局：倒计时结束前 0.33 秒踩油门、加速、右漂移、松开接小喷、暂停、名次表 | 完美起步、漂移、小喷各触发一次；没有页面报错 |
| `game_check.py ai` | 电脑代开玩家的车跑完一场 1 圈的比赛 | 71 秒冲线并进入结算；已完赛的五辆车单圈是 70.5～72.1 秒（截图时还有一辆没到）；没有报错 |
| `game_check.py item --sec 75` | 道具赛 2 圈，每 2.5 秒往各辆车手里塞一件道具 | 75 秒里六辆车用出 140 件道具：命中 20 次、被打转 20 次、天使挡下 6 次；材质数值都是有限数，没有黑屏重拍 |
| `pixel_check.py` | 读回 HDR 场景缓冲：控制组，再逐个触发冲击波、护罩、磁铁、氮气、香蕉、导弹、水炸弹、两种爆炸，最后让电脑混用全部道具 14 秒 | 扫了 1047 帧，非有限的像素是 0 |
| `audio_check.py` | 声音冒烟：第一次点击后音频启动，每个音效和接口都能调用，三首曲子能切，静音有效 | AUDIO OK，控制台没有报错 |
| `audit_geo.py` | 顶点色审计：用顶点色的材质必须有顶点色 | BLACK 0 |
| `glsl.py` | 启动诊断：着色器编译错误、控制台报错、启动各阶段耗时 | errors / warnings 0 |
| `perf.py`（白天、夜晚各一次） | 3 个画质档 × 2 种分辨率的单帧渲染耗时（渲染后读回一个像素逼 GPU 同步，先连续画两三秒预热，30 帧取平均，两轮取小） | 见下表 |

**单帧渲染耗时**（含阴影、海水倒影、全部后期；比赛中约 440 次绘制、131 万个三角形）：

| 分辨率 | 流畅 | 均衡 | 极致 |
| --- | --- | --- | --- |
| 1600 × 900 · 午后 | 3.08 ms | 4.75 ms | 5.57 ms |
| 1600 × 900 · 夜晚 | 2.84 ms | 5.21 ms | 4.89 ms |
| 1920 × 1080 · 午后 | 2.94 ms | 5.61 ms | 5.71 ms |
| 1920 × 1080 · 夜晚 | 2.86 ms | 8.79 ms | 8.88 ms |

大厅开着景深，极致档是 5.5～7.9 毫秒。

**这些数字有浮动。** 同一个包在一小时前另跑过一轮：1600 × 900 极致档午后 5.04、夜晚 5.01 毫秒，1920 × 1080 午后 6.43、夜晚 5.82 毫秒。同一个格子前后两轮最多差 3 毫秒，原因没有细查（多半是机器上别的程序在抢资源）。所以看量级就好：极致档一帧 5～6 毫秒，偶尔更高。

**两处会干扰测量的环境因素**，都和游戏本身无关：

- **远程桌面的 32 Hz**：浏览器里的 `requestAnimationFrame` 最高就是每秒 32 次，帧率这个数字没有意义，所以只报单帧耗时。
- **能效核**：这台机器的 CPU 是 6 个性能核 + 4 个能效核。Windows 有时会把无头的浏览器排到能效核上——同一个包、同一帧，极致档从 5 毫秒变成 12～13 毫秒，用性能剖析器看，时间都花在脚本提交绘制上（每帧 11.8 毫秒），显卡只用了三成多。按真实时间写的按键脚本也会因此错位（“完美起步”没触发、车在等截图的时候撞了墙）。检查脚本启动浏览器后会把它的进程钉到性能核上，之后的数字才稳定。平时玩的时候浏览器在前台，本来就跑在性能核上。

**启动各阶段**（`performance.now()`，从开始启动算起，无头 Edge）：0.4 秒渲染舞台就绪，0.73 秒贴图烘完，1.2 秒世界建完，4.4 秒场景就绪。最后一段是显卡编译着色器，放在加载界面后面。

**在真实窗口里另打开过一次**：用系统 Edge 直接打开 `index.html`，截屏确认大厅正常，并且已经在赛道上跑起来（跨海大桥，113 km/h）。

## 3. 看过的画面

以下都是打开截图逐张看的，属于目视判断，不是数值：

- 大厅（车库里的环绕镜头）、车库翻页、操作说明面板、暂停面板、结算面板。
- 自由镜头下的五个机位：城市鸟瞰、跨海大桥起点、商城发卡弯、穹顶广场、斜拉桥塔。
- 一场比赛里的开场镜头、漂移、氮气、冲线慢放、结算。
- 道具赛里的道具箱、天使护体（带翅膀和地面光环）、导弹及烟尾、水炸弹、爆炸冲击波、磁铁光束的特写。
- 上午、白天、午后、黄昏、夜晚五个时刻的比赛画面。
- 调试道具赛黑帧时，从录像里抽出来逐帧统计的亮度数据，以及其中几帧的画面。

看到并改掉的（按发现顺序）：

- 树篱、护栏、桥面板是黑的：扫掠几何的颜色回调返回了数组而没有写进输出，材质拿不到顶点色。
- 道具箱上挂着一片片白面：实例化网格配了线框几何，被当成三角形画了。换成十二条细长的小方块拼成的框。
- 玻璃幕墙是不反光的白色：那个材质从来没有定义过，three 静默换成了无光照的默认材质。补上材质，并让合批器遇到未定义的材质直接报错。
- 车身左侧的字是镜像的：左侧贴图带在车上转了 180°，画字的时候要转着画。
- 开场镜头和冲线镜头是整页空白：电影黑边的 CSS 类名同时命中了 `body.cine`，页面被改成了固定定位、高度 0。
- 开场镜头里能看见名次、圈数这些占位内容：开场期间把界面藏起来。
- 开场镜头里自己的车跑到画面右边去了：大厅为了给菜单让位而做的镜头偏移，在开场镜头里被重新加了回去。
- 夜晚过曝：夜晚的曝光是白天的八倍，自发光、车灯、道具的亮度没有跟着换算。
- 大厅的环绕镜头转到桥墩后面：镜头方位角有两套约定，相差 90°。
- 挡在镜头和玩家之间的对手把画面挡住了：离镜头近的对手变透明。
- 贴墙时镜头被横着推到车顶上，有时被甩进墙里：改成沿着“车到镜头”这根杆往回收，收到路面里为止，车始终在画面正中。
- 冲线后的环绕镜头跟不上还在滑行的车：改成刚性跟随。
- 高速加氮气时镜头被落得很远、车缩成一个小点：镜头原来在世界坐标里平滑，车速越快落得越远；改成先跟着车平移、再平滑横向摆动，并收小氮气时的视野和后拉。
- 第一次出现某种特效时卡一下：着色器第一次编译。开场前把所有着色器预热一遍。

## 5. 自己定的规则和数值（没有官方资料）

- **赛车**：沿用了原作里几辆车的名字和分级，数值是按风格估的。

  | 车 | 级 | 极速 | 加速 | 氮气 | 小喷 | 集气 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 新手赛车 | D | 174 km/h | 8.4 m/s² | +60 km/h，2.3 秒 | +26 km/h，0.46 秒 | ×0.92 |
  | 雷电 | B | 196 | 9.8 | +70，2.6 | +32，0.50 | ×1.12 |
  | 雷诺 | A | 204 | 10.6 | +76，2.9 | +34，0.52 | ×1.00 |
  | 针尖 | A | 208 | 10.2 | +78，2.8 | +36，0.54 | ×1.16 |
  | 流火 | A | 206 | 10.9 | +75，3.1 | +33，0.52 | ×1.00 |

- **技巧的判定**：漂移至少攒够 0.13 的“漂移角 × 时间”才给小喷（约 0.35 秒起），松开 Shift 后 0.6 秒内再按 ↑ 有效；完美起步是 GO 之前 0.45 秒内按下 ↑；漂移最多带两瓶氮气。
- **道具**：天使 6 秒，磁铁 5.5 秒；导弹、水炸弹、香蕉皮把车打转的时间分别是 1.7、1.6、1.3 秒。抽到什么按名次给概率：领跑的（香蕉 30%、天使 32%、导弹 18%、水炸弹 20%），居中的六种都有，落后的（导弹 34%、磁铁 30%、氮气 22%、水炸弹 14%）。
- **电脑车手**：三档难度分别是 0.92 / 0.98 / 1.04 的技能系数；离玩家太远会按差距把技能在 −7% 到 +10% 之间微调（橡皮筋）。车手的名字是虚构的。
- **电脑车手开车的几个手感参数**（提前量、起漂移的横向加速度阈值、刹车和收油的余量）是用 `tools/qa/race_sim.mjs` 和 `sweep.py` 扫出来的，目标是六辆车都能跑完整圈、圈速在 70 秒上下。
- **三首背景音乐**、界面上的文案、结算里的技巧统计口径，都是自创的。

## 6. 验证过程中修掉的问题里最值得记的一个

**道具赛整屏黑帧。** 现象是界面还在、3D 画布偶尔全黑 0.5～1 秒，CPU 侧没有任何异常。按道具类型分别录像数黑帧：导弹 234 帧、水炸弹 199 帧，天使、磁铁、香蕉十几帧，纯竞速 0 帧。

- 排除法：关掉环境光遮蔽没用，关掉泛光黑帧归零——说明画面里有坏像素，被泛光的模糊抹到了全屏。
- 读回 HDR 场景缓冲、逐通道检查半精度的指数位，确认坏像素是 NaN；按绘制调用二分（冻结一帧，只画前 N 笔），定位到冲击波亮环这一笔。
- 根因：`itemFx.update(..., fx)` 的参数名把外层的 `fx` 对象遮蔽了。函数里的 `fx.f`（夜间亮度系数）取到的是粒子系统上不存在的属性，透明度算成 NaN，加色混合就写出了 NaN 像素。改名后逐个特效复查，非有限像素归零；六种道具各录 20 秒，黑帧 0。
- 另外加了两道防线，坏像素只坏自己那一块、不会再连累整帧：进泛光之前按位检查指数位；镜头光晕在画面别处取三个点采样，取回来的颜色也检查。写防线时踩到一个坑：`texel != texel` 和 `isnan()` 在 Edge 的着色器编译器下会被当成“永远不成立”优化掉，注入 NaN 试出来仍然全黑；改成按位看指数位才管用。
- 回归检查：`tools/qa/pixel_check.py`，带 `--inject` 自检（故意把亮度系数改成 NaN，工具必须报错）。

另外两处是写测试时发现的玩法问题：断位双喷原来几乎按不出来（起漂到松开要 0.5 秒以上，低速时收漂移的窗口不够），把给小喷的门槛从 0.22 降到 0.13；香蕉皮命中的事件里没有“谁丢的”，命中有发生但没记到统计里。

还有一处是入库前自检时发现的：浏览器本地存的设置不校验，圈数存成 0 的话比赛一开就结束。现在不在选项里的值都退回默认。

## 7. 没验证的

- 只在 Edge + 这一张显卡上跑过（以无头模式为主，另在真实窗口里打开过一次）。Firefox、Safari、核显、别的显卡都没测。
- **本地显示器上的帧率没有量过**：测试时这台机器是通过远程桌面连着的，拿得出手的只有单帧渲染耗时。
- **声音没有听过**：只验证了音频能启动、每个音效都能调用、不报错，音色和响度没有经过耳朵。
- 漂移的手感、难度是否合适、电脑车手像不像人，只能人来判断。
- 没有做长时间的浸泡测试（反复开局、来回切大厅几十次）来看资源有没有慢慢泄漏。
- 没有独立代码审查：只有作者自己的定向自查。

## 8. 做不到的

- 模型全是代码拼的：赛车是放样出来的壳体，近看比商业游戏简单得多，座舱玻璃是不透明的、里面没有车手。
- 赛道的尺寸是按小地图换算的，弯道半径和路宽是估的；路面是平的，没有坡度和跳台。
- 电脑车手是脚本 AI，会走赛车线、漂移、用道具，但不会配合战术。
- 只有和电脑比赛一种方式：没有联网、录像回放、改装、宠物这些系统；操作需要键盘。

## 9. 怎么复现

```bash
npm install
npm run prod                       # 重新打出压缩版 app.js（仓库里已经带着）
python tools/qa/run_all.py         # 第 2 节的整张表，约十二分钟，日志写进 docs/evidence/
python tools/qa/gallery.py         # 重出 README 里的 16 张截图
```

需要 Python 3.12+、`pip install playwright pillow`、系统里的 Edge。画赛道平面图另跑 `node tools/qa/plan_check.mjs --json tools/qa/plan.json` 和 `python tools/qa/plan_map.py`（输出的图不随仓库分发）。

## 观察到了什么

以下都是我打开截图后实际看到的。

- **主角可辨**：侧面、正面、四分之三、俯视与特写下，鹈鹕（长喙 + 下垂的浅金色喉囊 + 珊瑚红头盔 + 白色身体）和巡航车（薄荷绿车架、奶油色轮胎、挡泥板、车筐、弹簧座、车尾三角旗）在总览距离就能认出。特写下能分辨眼睛与高光、眉毛、眼周裸皮、下颌带、冠羽、喙尖红甲。
- **运动中的连接**：侧跟、特写、环绕截图里，蹼足在踏板上、翼指握在把套上、颈从胸口伸进头部，没有看到断开或悬空。单元测试保证整圈踏频里腿都够得到踏板。
- **画面层次**：前景的栏杆、路灯、长椅；中景的山坡、棕榈、灯塔；远景的远岛与云。雾色与地平线一致。
- **时刻**：黄昏是暖桃色天空配紫色路面；夜晚天空有星，路灯在步道上留下分开的暖色光斑，车灯照亮前方，远处栈桥的灯亮着；清晨天空偏粉。
- **画风**：排线是淡彩加交叉排线；线稿是纸白底、墨线、只在暗部排线，天空留白、太阳只剩一个墨圈，海面只留岸沫的墨线。
- **跃鱼**：定点相机连拍 4 帧，鱼沿抛物线腾空，入水处有水花和扩散的涟漪环。
- **鹈鹕视角**：能看见自己的喙尖和前方的路，没有被头颅内壁挡住。

### 过程中发现并修掉的问题

这些是验收和截图**抓到**的缺陷，按发现顺序：

1. 放样体表面出现网格花纹：每个四边形的第二个三角形绕序反了，描边壳从网格里透出来。
2. 喉囊不够深、与上喙同色，读起来像鸭嘴；头盔太大像兜帽。加深喉囊、分成两种颜色、放大头部并把头盔上移。
3. 躯干前倾时头跟着前栽。改为头部目标不跟随俯仰，并加弹簧滞后。
4. 围巾顺侧腹下垂。调整升力与碰撞体，并给布料加了抗弯约束（中间还修掉一个把约束连到下一行而不是下两行的 bug）。
5. 海面在细网格与粗网格交界处有一道颜色台阶（深度没有饱和）；正对太阳时碎金密得像网格。
6. 鹈鹕视角被自己的描边壳和头盔挡住半边。
7. 灯塔光束像一块灰色半透明板子（双面叠加、无沿程衰减）。写了专用的光束材质。
8. 路灯光斑范围 17 m、灯距 27 m，互相重叠，看不出“一汪一汪”。收紧到 10.5 m。
9. 全局时钟在重写仿真函数时漏掉，时间不推进（验收脚本的暂停检查两边都是 0，才暴露出来）。
10. 自动画质按帧率判断，在无头浏览器里被出帧节拍误判。改为量单帧真实耗时。
11. `V`（画风）和 `N`（音乐）在帮助里写了但没映射。
12. 排线 / 线稿画风下天空和海不跟着变。
13. 检视层的骨线画在肢体内部被挡住；改成细圆柱骨段、关节球和实体踏频圈。
14. 每次重建鹈鹕泄漏两张 Canvas 贴图（40 次后 23 → 105）。改为共享贴图。
15. 在鹈鹕视角内重建鹈鹕后，头部自遮挡件重新出现。
16. 焦点在按钮上时空格 / 回车被全局按键抢走；开场卡片没有焦点陷阱；隐藏界面后按钮仍在 Tab 序列里。
17. 手动选“低”画质只改了开关，阴影灯要到下次调色盘更新才关。
18. 主按钮墨字对比度 3.89:1，折线图刻度文字 2.92:1。
19. 海鸥受惊时高度在一帧里瞬移 14 米。加了爬升限速。
20. 清理“未使用”代码时删掉了一个风场在用的变量，页面无法启动——重新跑验收时发现并恢复。

## 不确定的

- **听感**没有验证。音频引擎的作者用分析器量过各音效的 RMS 和峰值、静音与恢复、节拍跟随；但音色是否好听、混音是否平衡，只有自己听一遍才知道。
- **只在 Chromium 内核上测过**（Edge 158 与 Playwright 的 Chromium）。Firefox 和 Safari 没有实测，包括 `backdrop-filter`、`file://` 下加载内嵌字体、WebAudio 在这些浏览器上的行为。
- **低端显卡上的表现没有实测**。本机单帧成本最高 6 ms；自动降档逻辑存在，但降档路径没有在真正慢的机器上跑过。
- **触屏只在仿真环境测过**（Playwright 的触屏仿真），没有在真机上试过拖动和双指缩放。
- **海鸥的飞行路线**是绕固定中心的圆，受惊后半径变大，可能会穿过棕榈树冠；没有逐帧核对。
- **独立代码审查没有完成**。派出的审查代理启动后即被 API 用量上限拒绝，没有产出。我自己按给它的清单做了定向自查（上面第 11–19 条来自这轮自查），但这不等同于一次不受作者思路影响的审查。
- **广色域 / HDR 显示器**上的颜色没有看过。
- 自动化截图是在无头浏览器里拍的，与有头窗口的实际观感可能有细微差别（例如合成顺序）。

### 这轮发现并修掉的问题

1. **大气积分器把地平线算暗了**：等距采样在贴地视线上全落在稀薄高层。改成按密度标高布点后仍不对，回手算物理上界才发现视线透射率被阳光透射率覆盖（两次取样共用了一块缓冲）。
2. **从写实切回赛璐璐时材质没有换回去**：换装按“当前材质是不是赛璐璐”识别网格，而此刻网格上挂的是 PBR。验收脚本原先只查状态标志，是补了“数一数可见网格用的什么材质”才抓到的。
3. **只在写实下显示的棕榈小叶卡片一直用的是赛璐璐材质**（可见性判断后提前返回，没走到换材质）。
4. **路面边缘的锯齿色块**：改造前就有的缺陷，俯视图里才看得出。三处原因叠在一起——步道下面只压低 5 cm（比路面还高，从路缘石一侧冒出来）；紧贴步道的草坡可以比步道面高；一格宽的路面条带能从格子两个角之间斜穿过去。修法：步道下压到路面以下、`terrainHeight` 加路肩、中心点也测一次，并补了回归测试。
5. 标定函数把换档后的一次性开销算进帧耗时；阴影贴图一帧画三次；GLSL 整数字面量传给 `float` 形参；`BokehPass` 不读真实深度。
6. 竖屏手机被 2:1 黑边切掉大半画面 → 只在画面比 3:2 宽时加边。

### 不确定的

- **造型的写实程度**受几何本身限制：近景里鹈鹕有了羽毛叠瓦、奶油白和绒毛边，但比例与轮廓仍是卡通的；棕榈树干、灌木球、云朵的几何没有重做，靠噪声法线与轮廓侵蚀“打散”。
- 多次散射是经验补光（系数 0.12 让正午天顶亮度对上记忆中的实测值），不是严格解；地平线一带比真实晴空略灰。
- 帧耗时的数字只在无头 Edge + RTX 3080 上量过，且波动较大； Firefox、Safari、核显都没有实测。Half-float 多重采样渲染目标需要 `EXT_color_buffer_float`，没有时退回 8 位缓冲（泛光质量下降）。

## 第三轮：入库前自查（2026-11-24 夜 – 11-25）

### 发现并修掉的问题

1. **触屏设备上，速度仪表压住了触屏按钮。** 第二轮给电影黑边加的抬升规则（`body.has-bars .ride-card { bottom: … }`）比触屏规则（`.ride-card { bottom: 88px }`）的优先级高，在手机和平板上把仪表压回屏幕底部，盖住四个触屏按钮；同一条规则还让提示条从顶部跑到底部、让竖屏的设置面板从“贴底的半屏面板”变成几乎满屏。竖屏下黑边高度本来就是 0，这些抬升完全多余。修法：触屏和窄屏各补一条同等优先级的规则，把原来的位置写回去。之前的手机检查只断言“触屏按钮显示、无横向溢出”，没有量两者是否重叠，所以没抓到——是给 README 截手机图时看到的。
2. **打包产物里没有 three.js 的版权声明。** 打包参数是 `legalComments: 'none'`，three.js 源码里的 `@license` 注释（MIT）被压掉了，仓库里也没有许可证全文；MIT 要求分发时带上版权声明和许可声明。修法：改成 `legalComments: 'inline'`（`app.js` 多了 182 字节），把 three.js 的 LICENSE 原文放进 `licenses/three.js.txt`，README 的致谢指向它。字体（OFL）和图标（MIT）的许可证原本就随仓库带着。
